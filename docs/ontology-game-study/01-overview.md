# 3つのゲームから考える、オントロジーが効果につながる条件

整理日：2026年9月25日。対象は本プロジェクトで実装・検証した3つのゲーム操作システム。実装と検証記録に基づき、オントロジーの適用条件を考察する。

## この4本の読み方

本書が全体の見解をまとめる入口である。詳しい経緯と証拠は[テトリス](02-tetris.md)、[マリオ](03-mario.md)、[スイカゲーム](04-suika.md)へ分けた。既存の技術資料・ログは証拠資料として保持し、結論の参照先をこの4本に集約する。

## 結論

今回の検証からは、オントロジーの適用しやすさを「対象を明確に定義できる」「動きが決定論的である」だけで説明するのは不十分だった。

**状況と行動の意味を定義でき、その行動の成功を判定でき、成功へ向けて制御できることが、効果につながる重要な条件と考えられる。** さらに、局所的な成功が全体の目的に結びつくかも必要になる。

- テトリス：定義した関係と、一手の結果を計算・照合しやすい。
- マリオ：目的・適用条件・継続・成功・中断を持つSkillを制御につなげ、クリアする構成へ改善できた。
- スイカ：対象・種類・関係というセマンティック層は定義できた。一方、衝突が周囲へ波及するkinetics（操作後の物理的な動き）について、盤面全体にとって何を成功とするかを定めにくかった。知識とSkillを増やしても、継続的な得点向上の確認に至らなかった。

したがってスイカは、**今回の観測・操作方式ではオントロジー導入の効果が出にくかった事例**として位置づける。適用不能の証明ではないが、追加投資に見合う効果が確認できず、検証を一旦終了する判断は妥当である。「まだ改善できる可能性がある」ことと「改善を続けるべき」ことは同じではない。

## 本研究でいうオントロジー

対象・属性・関係に加え、行動の目的、対象、適用条件、期待する状態、成功・中断条件を明示した判断知を指す。Skillは、その行動に関する知識を実装する単位として扱う。

例えば「ジャンプする」という行動だけでは、何を達成するために跳ぶのかが曖昧である。同じジャンプ入力を使っても、敵を避ける、穴を越える、段差を上るでは成功基準が異なる。そこで、目的と成功基準の違いに応じて、曖昧なジャンプを複数のSkillへ分けた。

| Skill | 目的 | 成功として確認する状態の例 |
|---|---|---|
| JumpOverEnemy | 対象の敵を越える | 敵の先へ進み、着地する |
| CrossGap | 対象の穴を越える | 対岸の足場へ生存着地する |
| ClimbStep | 段差を上る | より高い足場へ着地する |

成功基準が異なるため、踏切位置、横入力、ジャンプの継続時間、終了や中断の条件も変わる。この意味づけを観測と制御へ結びつけることで、「跳んだら終わり」ではなく、それぞれの目的を達成するまでの一連の行動として扱える。表は意味の違いを示す要約であり、厳密な実装条件は[マリオの詳細](03-mario.md)から参照できる。

RDF／OWLや汎用論理推論エンジンを導入した実験ではなく、Python・JavaScript・JSON・条件分岐で表現した。成功条件を記述すれば制御が自動的に成立するわけではなく、その条件に向けた操作とフィードバックの実装が必要である。関係の定義、戦略上の優先順位、制御上の閾値は区別して管理する。

| kineticsの成功条件 | 配置・消去後の状態を計算できる | 対岸着地・取得など目的と終了を対応付けやすい | 合体・周囲への波及・空間・将来の経路を含む「良い結果」を定めにくい |

| 周囲への影響 | 消去後の変化をエンジンで計算 | 主に自分と局所的な敵・地形 | 複数駒へ衝突・回転・支持変化が波及 |
| 結果照合 | 再計算しやすい | 対象状態を確認しやすい | 遮蔽・誤認識・個体追跡不足で不明が多い |

| 得点・攻略効果 | 知識追加の因果効果は未測定 | システム全体の改善を確認 | 継続的な得点向上は未確認 |

テトリスはターン制の簡易実装、マリオはRAM観測と既知ステージ、スイカは画像観測である。ゲームだけでなく観測・操作条件も異なるため、横並びの得点や成功率で優劣を比較しない。

## スイカ：意味は定義できても、動きの成功を定めにくい

スイカでも「同じ種類」「合体後の種類」「上にある」「接触する」「支持する」といった対象・関係は定義できる。主な難しさは、こうしたセマンティック層を記述できないことではなく、**それを使って操作した後、どの状態になれば良い一手だったといえるか**にある。

例えば、落下駒が直接合体しなくても、その衝突で別の同種ペアが合体すれば目的を達成し得る。逆に、狙ったペアが合体して加点されても、周囲の小さい駒が大きい駒の下へ潜り込み、次の合体経路を失えば、長期的には不利な一手かもしれない。

| 成功に含めたい観点 | 定義を難しくする点 |
|---|---|
| 直接・間接の合体 | どのペアをどの順に合体させることが有益かが盤面によって変わる |
| 空間を理想的に保つ | 空き面積だけでなく、空間の位置・形・次の駒が通れる経路も重要になる |
| 小さい駒の孤立を防ぐ | 投入時に覆わなくても、衝突後の滑り・回転で下へ潜ることがある |
| 次の合体や連鎖につなぐ | 今の得点と、数手先の可能性との優先順位を決める必要がある |

そのため「合体したら成功」「高さが下がれば成功」といった単一条件では、盤面全体の価値を十分に表せない。どこまでの影響を評価し、何手先までを見て、得点・空間・将来の経路の競合をどう解くかまで定める必要がある。周囲の状態が連動して変わるほど、状況をまたいで使える成功条件の構成は難しくなる。

これは単に実行結果が予測しにくいという問題に加え、**何を望ましい実行結果とするか自体が複合的で、文脈に依存する**という問題である。ただし、条件が複雑であることは定義不可能を意味しない。また、結果の揺らぎだけで定義が不可能になるわけでもない。今回の構成では、十分な成功定義を作り、それを予測・制御・観測へ結びつけることが難しかった、というのが検証からの見解である。

## 「成功を定義できる」を4つに分ける

1. **定義可能性**：何が起きれば成功か。対象ペアの合体自体はスイカでも定義できる。
2. **判定可能性**：実際に成功したと観測できるか。別のペアの合体による加点を誤って成功扱いしない。
3. **達成可能性・制御可能性**：選んだ入力で成功へ近づけるか。実行中の補正や回復手段があるか。
4. **全体目標との整合**：局所成功が長期的な得点や生存に寄与するか。合体しても小さい駒を埋めて将来の手を失う場合がある。

マリオでは目的までの過程をSkillとして定義し、制御で追従できた。スイカでは投入後の波及が大きく、局所成功と配置全体の良さが一致するとは限らなかった。これが今回の中心的な学びである。

## ランダム性についての見解の更新

当初の仮説は「意味を符号化しやすく、動きが画一的・決定論的な領域ほど向いている」だった。マリオの改善から、動作が複雑でも、観測・成功条件・継続制御がつながれば適用できると分かった。

更新後の仮説は「成功条件と制約を定められ、それを観測し、制御可能な範囲で達成できる領域ほど効果につなげやすい」である。未知の入力や観測していない速度・回転・接触状態も結果を不確かにする。スイカの難しさを物理エンジン自体の真の乱数性と断定する測定はしていない。

## 実務へ持ち帰る観点

適用を検討する際は、**セマンティック（対象・関係・行動の意味）を定義できるか**と、**kinetics（その行動を実行してから結果に至る動き）を成功へつなげられるか**の両方を見る。実務におけるkineticsは、本報告では物理運動に相当するものとして、API処理、業務フロー、待ち時間、他者の操作などを伴う状態変化まで含めて考える。

| 観点 | 実務で確認すること | ゲームからの学び |
|---|---|---|
| セマンティックの定義 | 対象・属性・関係と、行動の目的を明確にできるか | スイカでも同種や合体関係は定義できた。意味を整理できるだけでは成果は保証されない |
| セマンティックとkineticsの接続 | 行動の目的を、実行可能な条件・手順・成功基準へ落とせるか | マリオでは曖昧なジャンプを目的別のSkillへ分け、制御へ接続した |
| kineticsの成功条件 | 直接の成果だけでなく、周囲への影響や将来の選択肢を含めて良い結果を定められるか | スイカでは合体しても別の駒を埋める場合があり、局所成功と全体の良さが一致しなかった |
| kineticsの制御 | 実行途中の変化を観測し、修正・中断・回復できるか | マリオは継続的に操作できるが、スイカは投入後の駒を直接補正できない |
| 結果の照合 | 定義した成功条件と、実際の対象の状態変化を対応付けられるか | テトリスは再計算できた一方、スイカでは遮蔽や認識誤差で判定不能が多かった |

例えば業務で「承認する」と定義できても、その実行中に在庫や申請内容が変わるなら、承認時点の条件の再確認、処理の中断、完了後の整合性確認まで設計する必要がある。これはセマンティックに定義した目的を、kinetics上でも成立させるための設計に相当する。

**セマンティックを明確にできても、kineticsの成功条件が定めにくく、予測・制御・結果確認も難しい場合、導入効果は出にくくなり得る。** その場合はルールを増やすだけでなく、対象範囲の限定や観測・実行環境の改善、あるいは導入を見送る判断が必要になる。これは本事例からの設計上の示唆であり、全業務に対する実証済みの一般則ではない。

## 成果の解釈と、追加検証の限界

マリオでは、対象や関係に加え、行動の目的・適用条件・継続・成功・中断条件を判断知として定義し、認識と制御へ反映した結果、クリアする構成へ改善できた。本報告では、この一連の意味づけと実装への接続をオントロジーの適用として捉える。認識処理や制御コードのすべてをオントロジーと呼ぶのではなく、定義した判断知がそれらを方向づけたという整理である。

**改善箇所と実行結果の対応から、オントロジーの適用が改善に大きく寄与したと考える根拠がある。** 例えば、頂上への着地を次の穴越えに進む条件として定義し、既知の失敗場面で改善を確認した。取得行動に安全な位置への移動と敵待ちを含めることで、通しプレイでもフラワー取得につながった。厳密な比較実験によって寄与の大きさを確定したわけではないが、認識や制御も変更したことを理由に、オントロジーの効果と切り離すのは本事例の捉え方に合わない。

一方、3ゲームで確認できた成果の範囲は異なる。テトリスは構成・検証のしやすさ、マリオは判断知を実行につなげた改善、スイカは改善を重ねても得点効果を確認できなかったことが主な知見である。「テトリスは知識追加で得点改善に成功した」「マリオは100%クリアできる」「スイカにオントロジーは適用不能」とまでは結論しない。スイカのABBAも、同じ候補戦略に対する入力形式の比較であり、適用全体の効果を直接測るものではない。

**現状の構成で試行回数だけを増やしても、効果の確かさや適用条件の理解が十分に進むとは限らない。** 追加検証は原理的に不可能ではないが、測定環境や比較設計を整備する負担が大きい。そのため、今回の検証はここで区切り、確認した改善と限界を実装事例に基づく知見として残す。

本報告は、オントロジーの寄与が示唆された改善事例と、効果につながりにくかった事例を対比するものである。意味の定義が実行と結果へつながる条件を具体例から示すとともに、スイカで得点効果を確認できなかったことも、その難しさと導入コストを理解するための検証成果として位置づける。
